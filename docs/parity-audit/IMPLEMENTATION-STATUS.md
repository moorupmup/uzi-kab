## Этап 4 — исследования и комплекты дополнены

- `src-tauri/src/lifecycle.rs`: мягкое удаление исследования и восстановление прежнего статуса, revision, журнал и сохранение всех полей. Для исходного legacy:2 прежний статус неизвестен: восстановление переводит запись в черновик, о чём сообщает интерфейс. Сохранение удалённого исследования не обходит восстановление.
- Удаление/возврат исследования: администратор — все, врач — только свой doctor_id, включая архив, просмотр — запрещено. Старое исключение для редактирования legacy не расширяет право удаления.
- Фильтр списка «Все действующие / Черновики / Завершённые / Удалённые / Все, включая удалённые», с поиском и пагинацией. История пациента сохраняет удалённые записи с отметкой; в новый комплект они не выбираются.
- Меню «Ещё» редактора: полный предпросмотр и удаление/восстановление. Предпросмотр и печать сохранённого исследования используют один ProtocolDocument; старый дублирующий печатный блок редактора удалён. Несохранённая форма не выдаётся в печать как сохранённый документ.
- Удалённое исследование доступно для просмотра, редактирование и печать закрыты до восстановления. При прямой печати страницы CSS также исключает удалённый документ и вложения и выводит пояснение.
- Автоматическая миграция `lifecycle_v1` с резервной копией и одной транзакцией: 5 legacy_container / 10 legacy_research переносятся в существующие study_bundles / bundle_items; mapping обеспечивает повторный запуск без дубликатов. Пациент и каждая ссылка проверяются; некорректная ссылка откатывает всю миграцию, исходные таблицы сохраняются.
- **Порядок старой печати проверен по ProtocolHandler.class**: `SELECT protocol_id FROM RESEARCH WHERE container_id=? ORDER BY protocol_id`. Миграция использует protocol_id,id, а не порядок ID связей. Доказательство и SHA-256 исходного класса: docs/parity-stage4-order.json.
- Архивные комплекты открываются независимо от правил создания новых (в том числе архивный черновик с отметкой и явной проверкой). Новые комплекты по-прежнему требуют завершённых исследований одного пациента; выбор на странице пациента передаётся в порядке истории.
- У комплектов отдельное удаление/возврат, состав не удаляется. Администратор управляет всеми комплектами, врач — созданными им; просмотр не меняет данные. В истории есть показ удалённых комплектов.
- Для каждой ссылки сохраняется revision исследования. Изменение после создания отмечается и требует проверки текущих документов; удалённый/недоступный/чужой пациенту элемент блокирует печать, не исчезая молча из состава.
- Перед печатью сервер сверяет текущие ID/revision со всем показанным составом и состоянием комплекта. Изменение после открытия блокирует выдачу до обновления. Прямая печать страницы комплекта без проверки через кнопку выводит пояснение вместо обхода проверки.
- `tools/preview.ts` учитывает фильтр статуса. Новые события журнала локализованы. Основное меню, карточки справочника, две основные кнопки сохранения и оформление документа сохранены.

## Дополнение D07 и браузерного просмотра — выполнено

- Ограничение совместимых вариантов снято: «Добавить вариант» теперь по умолчанию создаёт **собственный текст**, исходное поведение остаётся доступным выбором. Администратор может добавить произвольную подпись без выбора прежнего медицинского смысла.
- В снимке варианта используется marker `__text`. Печатные условия сравнивают сохранённый собственный текст, условия JS редактора используют новый ID (исходный __other). Код из текста не исполняется.
- `renderLegacy` отслеживает действительно выведенные поля, включая вывод через переменные. Видимый свободный вариант, который исходная форма не вывела, добавляется как параметр с подписью органа/группы и поля. Прямо выведенный текст не дублируется.
- Намеренно свёрнутые родительские ветви не печатают свои сохранённые свободные дочерние значения. Значения остаются в записи, как в прежних условиях редактора.
- Подпись варианта, семантика, тип и подпись поля восстанавливаются из снимка; переданные клиентом label/baseValue/caption не подменяют их. Текст и подписи экранируются. Старый ID нельзя превратить в свободный вариант подменой поведения.
- Переименование справочника влияет на следующие записи; сохранённые документы и их повторное редактирование используют прежний снимок.
- В административном выборе поля теперь показана группа/орган, если она отличается от названия: одинаковые «Контуры» разных органов различимы.
- `tools/archiveReader.ts` заменяет пустую заглушку комплектов read-only preview. Читает native/перенесённые комплекты, состояния и изменения состава, снимки форм; до миграции показывает legacy_container/legacy_research с виртуальными ID только в памяти, сохраняя исходный порядок protocol_id. При наличии mapping не дублирует их. Ни один запрос просмотра не пишет в базу.
- Отсутствующий снимок/документ в браузерном комплекте даёт явную проблему состава и закрывает печать; остальные документы не пропадают молча.

Новые тесты проходят варианты селектов всех 16 перенесённых версий, прямой и дополнительный вывод, свёрнутую ветвь, экранирование, защиту метаданных и неизменность снимка после переименования/редактирования. Read-only reader проверен на немигрированной и мигрированной структуре, без записи и с отсутствующим снимком.

`docs/parity-free-options-native.json`: создание двух свободных вариантов через UI, выбор в форме, прямой и дополнительный вывод в настоящем exe, контекст органа, равенство предпросмотра печати, прежние подписи после изменения справочника и редактирования, новые подписи в следующих документах. ## Этап 5 — врачи и основные отчёты; R03 проверен ниже

- `src-tauri/src/doctors.rs`: административный список всех врачей, создание, переименование, скрытие/возврат, revision и аудит. Users.vue дополнен таблицей врачей и стандартным окном настройки; учётные записи остаются отдельной таблицей.
- `doctor_signatures_v1` фиксирует прежние подписи в study_signatures до переименований, с проверенной резервной копией. Для записи без указанного врача сохраняется пустая подпись, чтобы не придумывать имя и не менять прежние печатные заполнители.
- Новые документы получают текущее имя врача; правка с тем же doctor_id сохраняет прежнюю подпись. Намеренная смена врача фиксирует новую подпись, а прежняя попадает в audit. Новая запись на основе прежней получает текущую подпись назначенного врача, независимо от сохраняемого снимка формы.
- StudyEditor, ProtocolDocument/комплекты и read-only reader используют историческую подпись. API отдельно сообщает doctorCurrentName для текущего справочника. Переименование врача не меняет имя учётной записи.

Уточнение по названию вида сохраняет соответствие старых и новых названий одной type-ID конкретной строке агрегата.

## R03 — группы заключений: реализация и техническая проверка выполнены

- Группа хранится отдельно от свободного заключения в `study_decisions` и неизменяемом `decision_snapshots`. Нулевое назначение явно очищает группу и не возвращает исходную ссылку при следующем открытии. Отсутствующее поле старого клиента сохраняет прежнее назначение.

- Новое назначение проверяет активность всей ветви BASE.DECISION и принадлежность виду. Прежнее назначение сохраняется при обычной правке даже после удаления/переноса узла. Новая запись получает действующее назначение; копирование не обходит проверку активности.

- Статистика дополнена режимом «Группы заключений», фильтром ветви с потомками, переходом к исследованиям и CSV. Исторические пути и ID предков сохраняют смысл прошлой выборки при переносе ветви. Итоги, детализация и CSV используют один фильтр. В подробном списке этого режима показана группа.
