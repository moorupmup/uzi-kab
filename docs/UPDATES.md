# Обновление программы

Программа проверяет последний стабильный релиз `moorupmup/uzi-kab` при запуске, затем каждый час и при восстановлении подключения к интернету. Без интернета программа работает как обычно. Черновики релизов, предварительные версии, та же версия и более старые версии не предлагаются.

Внизу сайдбара после текущей версии появляются зелёный номер новой версии и круглая кнопка со стрелками. Подсказка: «Обновить программу». По нажатию срабатывает защита открытого несохранённого протокола, затем программа скачивает файл, проверяет размер и SHA-256, сохраняет проверенную копию базы `backups/before-app-update-*.db` и перезапускается. Во время скачивания работа с интерфейсом приостанавливается.

Временный процесс ждёт завершения программы и заменяет EXE по прежнему пути с прежним именем. Предыдущий EXE остаётся рядом как `*.before-update-*.bak`. Если замена или запуск нового файла не удались, выполняется попытка вернуть и запустить прежний EXE; ошибка записывается в `*.update-error.txt`. Это возврат при ошибке файловой операции или запуска процесса, а не определение всех возможных сбоев уже запущенной новой программы. Возврат старого EXE после изменения схемы базы может потребовать восстановления соответствующей копии базы.

Временные папки `.uzi-update-*` убираются при следующих проверках после завершения помощника. База, вложения и существующие копии при замене EXE не перезаписываются. Нужна локальная папка с разрешением записи.

## Как выпускать новую версию

1. Указать одинаковую новую версию в `package.json`, `src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json` (например `1.2.0`). Обновить lock-файлы обычной установкой зависимостей и сборкой.
2. Выполнить `npm run desktop:build` и `powershell -ExecutionPolicy Bypass -File tools/package.ps1 -SkipBuild`.
3. Создать в GitHub обычный опубликованный релиз с тегом `v1.2.0`. Прикрепить **один готовый переносимый EXE**, не установщик. Базу и персональные данные в релиз не включать. Имя скачиваемого EXE может отличаться от имени установленного.
4. Дождаться, пока GitHub подготовит SHA-256 файла (поле `digest` в API релиза). Отдельный JSON или файл контрольной суммы загружать не требуется.

Тег должен соответствовать версии внутри собранной программы: иначе после установки снова будет предлагаться то же обновление. Сокращённые теги вроде `v1.2` распознаются как `1.2.0`.

Релизы должны быть доступны публично без авторизации. Личные токены в EXE не встраиваются. SHA-256 сверяется с данными GitHub по HTTPS: это проверка целостности в рамках доверия репозиторию GitHub, а не независимая подпись издателя.

Первую сборку с этим механизмом необходимо установить вручную вместо прежнего EXE. Последующие версии можно получать кнопкой в программе.

## Проверки

`npm test`, `cargo test --manifest-path src-tauri/Cargo.toml`, `node tools/check-updater-ui.mjs` и `npm run desktop:build`. После сборки: `powershell -NoProfile -ExecutionPolicy Bypass -File tools/check-updater-helper.ps1` проверяет настоящий процесс-помощник на отдельных тестовых файлах, включая путь с кириллицей, пробелами и апострофом.

Проверка интерфейса использует вымышленные данные и подменяет транспорт команд и событий. Она проверяет появление версии, подсказку, размеры окна, ошибку скачивания и отмену обновления при несохранённом протоколе. Рабочая база не используется.
