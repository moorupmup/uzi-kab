# Кабинет УЗИ

Настольная программа для Windows 10/11 x64: Vue 3, Pinia, Tailwind CSS 4, Nuxt UI 4, Rust и Tauri 2. Нужны exe, `uzi.db` рядом и установленный Microsoft WebView2. Java, MySQL, Node.js и сервер на рабочем компьютере не нужны.

## Готовая папка

Новая сборка: `release/Кабинет УЗИ/Кабинет УЗИ — новая версия.exe`. Существующая база при упаковке не заменяется. Перед первым запуском закройте прежнюю программу и сохраните отдельную копию всей папки. Используйте локальную папку с разрешением записи, а не Program Files, сетевой диск или облачную синхронизацию.

При первом открытии создаётся проверенная страховочная копия перед обновлением схемы 1 → 2. Затем создайте первого администратора: старые пароли не используются, готового пароля нет. Старые exe обновлённую базу не открывают. Для возврата сохранена `backups/before-upgrade-*.db`.

Инструкция: [docs/WINDOWS10-ACCEPTANCE.md](docs/WINDOWS10-ACCEPTANCE.md). Автономный установщик WebView2 находится в `release/requirements`; подпись Microsoft проверена. После установки среды программа работает без интернета.

## Возможности

Подробная инструкция для врача: [открыть HTML-руководство](docs/Инструкция%20для%20врача.html). 17 разделов, семь скриншотов на вымышленных данных, поиск пациента, оформление, печать, снимки и резервные копии. Все изображения встроены: файл работает без интернета и находится также в готовой папке программы.

- Поиск по ФИО и номеру, фильтр пола, таблицы по 50/100/200/500 строк. Сортировка всей картотеки по ФИО, дате рождения и последнему исследованию нажатием на заголовок; пустые даты в конце. По умолчанию — последнее исследование, сначала свежие.
- Карточки, история исследований, скрытие и восстановление карточек без удаления истории. Неизвестную дату рождения можно оставить пустой.
- Новые исследования, черновики, завершение, свободное описание и поля исходных форм. Старые исследования редактируются напрямую, включая сохранённые параметры редких версий. Исходные таблицы и предыдущие значения сохраняются.
- Справочник пользовательских заготовок из прежней программы: поиск, разделы, фильтр вида исследования и вставка в текст исследования без замены введённого текста. Скрытые записи доступны отдельно.
- Точная версия шаблона, справочники, условные поля и расчёты щитовидной железы, ЭхоКГ, гинекологии и брюшной полости. Изменение размеров сбрасывает результаты. Расчёт необязателен: незаполненные размеры не мешают завершению и печати.
- A4 печать протокола и комплектов из 2–20 завершённых исследований одного пациента.
- Вложения PNG/JPEG/WebP до 25 МБ, MP4/WebM/AVI до 250 МБ внутри базы. Снимки включаются в печать; видео зависит от кодеков Windows, AVI сохраняется для внешнего проигрывателя.
- Статистика по периоду, видам, врачам и месяцам; CSV. Черновики, исходно удалённые и непривязанные записи исключены.
- Администратор управляет пользователями, врачами, копиями и архивом. Новые исследования врач создаёт и меняет от своего имени; старые исследования могут редактировать все пользователи с правом записи. Просмотр разрешает чтение, печать и экспорт, запрещает изменение данных.
- Пароли Argon2id, блокировка после 30 минут бездействия, сохранение формы в памяти при повторном входе. Файл не зашифрован: ограничивайте доступ средствами Windows.
- Ежедневная копия перед первым изменением за день, ручные копии, импорт и восстановление с паролем администратора. Перед восстановлением сохраняется текущее состояние. Копии автоматически не удаляются: регулярно переносите их на другой носитель.
- Контроль версии при сохранении, журнал предыдущих значений и действий. Один экземпляр новой программы на базу.

## Перенос и границы проверки

Перенесены 22 715 карточек (247 скрыты) и 72 019 исследований. Исходные 20 таблиц сохранены в `legacy_*`, включая BLOB. Все строки и значения сверены по SHA-256: `docs/migration-report.json`. Рабочая база пользователя тестами не изменялась.

Все 5 070 исходных записей с `pacient_id=0` оказались пустыми заготовками: 357 194 значения параметров, заключения и дополнения пусты; зарегистрированных вложений нет. По решению пользователя они удалены из рабочей картотеки, вкладка незавершённых записей убрана. При обновлении выполняется однократная очистка с проверенной копией `backups/before-empty-cleanup-*.db`. Заполненные, изменённые или связанные с вложениями записи не удаляются. Исходные таблицы `legacy_*` сохраняются. После очистки исходного набора остаётся 66 949 исследований; новые записи пользователя сохраняются отдельно от этих подсчётов.

Текст 16 фактически используемых известных версий сравнен с оригинальными JSP и RequestWrapper на 1 189 записях: расхождений после нормализации пробелов нет (`docs/template-parity.json`). Формулы четырёх видов сравнены с исходным JavaScript на 120 синтетических наборах. Это проверка переноса, а не клиническая валидация. Неизвестные версии показывают параметры с пояснением; другой шаблон не подставляется. Проверка не распространяется на все 187 исторических форм как редакторы. Макет адаптирован для A4, попиксельное совпадение со старой печатью не заявляется.

По решению пользователя обозначение объёма щитовидной железы «мм» сохранено с пояснением: при размерах в миллиметрах исходная формула выдаёт см³. При открытии архивные значения автоматически не изменяются.

Проверки: 18 Rust-тестов, 15 frontend-тестов, сборка exe и сценарии настоящего окна на синтетической базе (`docs/native-acceptance.json`). Локально Windows 11; Windows 10 и физический принтер проверяет пользователь по инструкции. Одновременная работа с нескольких компьютеров не предусмотрена.

## Разработка

Нужны Node.js 22.12+ (использовался 24), Rust, Visual Studio C++ Build Tools, Windows SDK и WebView2.

```powershell
npm ci
npm test
cargo test --manifest-path src-tauri/Cargo.toml
npm run desktop:build
powershell -ExecutionPolicy Bypass -File tools/package.ps1 -SkipBuild
```

В разработке Rust открывает `data/uzi.db`: для записи используйте отдельную копию и release exe рядом с ней. `npm run dev` даёт браузерный предпросмотр только для чтения на http://127.0.0.1:1420. В готовой программе HTTP-сервера нет. Минимальный экранный текст 14px, поля от 44px, в карточке пациента 46px.

Повторный импорт из отдельной копии MySQL: зависимости `tools/requirements.txt`, затем `python tools/migrate.py --port 13307 --output data/new-import.db`. Импортёр существующий файл не перезаписывает. Не запускайте исходную MySQL на единственном архиве. Данные, копии и приватные снимки не добавляйте в Git.
